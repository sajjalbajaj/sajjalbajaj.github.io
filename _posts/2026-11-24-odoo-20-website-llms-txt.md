**Short answer:** Odoo 20 provides a Website setting for creating an llms.txt file. Use it as a concise guide to useful public pages and authoritative information. It is not a ranking switch, a backlink, an access control or a promise that an AI service will cite the website.

## What does Odoo confirm?

The Website section of the [Odoo 20 release notes](https://www.odoo.com/odoo-20-release-notes) confirms the file option in Website settings. That establishes the publishing capability. It does not establish how every external AI system handles the file.

Avoid presenting the feature as a replacement for good pages. A summary cannot repair inaccurate service descriptions, inaccessible articles, broken links or contradictory information about the author.

## Which pages belong in the file?

Choose stable, public pages that help someone understand the organisation, its services and its detailed resources. Prefer a short description of each section over repeating entire articles.

For an illustrative ERP consultancy site, useful sections might include the consultant's verified profile, services, anonymised case studies, implementation guides and contact page. Include limitations where they matter, such as case studies that omit client names.

| Include | Reason |
| --- | --- |
| Canonical public pages | Stable destination for the reader |
| Clear section descriptions | Explains what each collection contains |
| Editorial or correction policy | Helps assess source responsibility |
| Current contact route | Provides a way to query inaccurate information |

Do not include internal proposals, customer records, private documents or unpublished drafts. A public file is available to people as well as automated systems.

## How does it differ from robots.txt and a sitemap?

These files serve different purposes. Robots instructions concern crawler requests, and a sitemap lists URLs for discovery. An llms.txt file offers a descriptive content guide. None should be used as a substitute for protecting sensitive material.

When content must be private, use actual access controls and verify that an unauthorised visitor cannot retrieve it. Merely omitting a URL from an index file does not make the destination private.

## How should the file be tested?

Publish a small initial version, request the public file and follow every listed link. Check the content type, readable text and canonical destinations. Include a redirect or renamed page in the maintenance review so old references do not accumulate.

For scheduled articles, ensure the public list does not expose them before their intended publication. Decide how the file will be refreshed when a guide moves or a collection grows.

## What would count as a useful outcome?

A maintained map of accurate public content is a reasonable implementation outcome. Increased AI citations would require separate observation; do not infer it from the file returning a successful response.

Use a dated sample of relevant questions and record any observed citations with their source URLs. Keep that measurement separate from the configuration checklist.
